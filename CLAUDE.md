# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

qview is a Windows-only image viewer, written in Rust with egui/eframe 0.36. Priorities: start-up speed, instant browsing, full keyboard control, no settings dialog. `README.md` / `README.ru.md` are the user-facing docs and must be kept in sync (both languages, cross-linked, formal tone). `doc/PERFORMANCE.md` / `doc/PERFORMANCE.ru.md` collect the measurements, estimates and decisions (test machine: i7-13700KF, RTX 4070 Ti SUPER, 3840x2160 at 240 Hz); add new measurements to both.

## Commands

```
uv run build.py                  # closes a qview.exe running from target\, then cargo build --release
cargo test                       # unit tests (view geometry, key map, folder order, decoder, mip levels, formats, SVG, thumbnails, folder tree, gallery grid, crop geometry, EXIF, saving, PDF, marks, duplicates)
cargo clippy --release --all-targets   # must stay warning-free
python tools/make_release.py     # tests, release build, dist\qview_<ver>_Setup.exe (Inno Setup 6, tools/setup.iss) and _portable.zip
python tools/make_release.py --no-tests --install   # the same, then installs it silently over the installed copy (closes it first; previous tasks reused)
$env:QVIEW_TRACE=1; .\target\release\qview.exe <file>   # start-up, decode and texture upload timings on stderr
$env:QVIEW_BENCH_FILE="<file>"; cargo test --release phase_timings -- --ignored --nocapture   # decode phases of one file
$env:QVIEW_BENCH_FILE="<file>"; cargo test --release histogram_timings -- --ignored --nocapture   # histogram counting, decoding with and without it (also read_again_timings, graph_timings)
$env:QVIEW_ANIM_FILE="<gif or webp>"; cargo test --release file_frames -- --ignored --nocapture   # frames and delays of an animation
$env:QVIEW_THUMB_DIR="<folder>"; cargo test --release thumbnail_timings -- --ignored --nocapture   # gallery thumbnails of a folder or an archive, twice: the second pass from qview's own cache
python tools/build_heif.py         # heif.dll (dav1d linked in) + libde265.dll into target\heif\bin (build.py and make_release.py run it, then copy them next to the exe; Meson, Ninja and NASM for dav1d go into target\heif\tools)
python tools/notices.py           # licenses\THIRD_PARTY_NOTICES.txt after the dependencies change (a test and make_release.py fail until then)
$env:QVIEW_HEIF_FILE="<heic>"; cargo test --release heif_file -- --ignored --nocapture   # libheif against WIC: header, decode times, pixel difference
$env:QVIEW_ARCHIVE_FILE="<cbr or cbz>"; cargo test --release archive_timings -- --ignored --nocapture   # listing, first/middle/last page, all in order, on 3 threads
$env:QVIEW_SVG_FILE="<svg>"; cargo test --release svg_file -- --ignored --nocapture   # parsing and drawing one SVG, the system fonts' loading
$env:QVIEW_THUMB_DIR="<folder>"; cargo test --release pdf_timings -- --ignored --nocapture   # a folder saved as one PDF (QVIEW_PDF_OUT keeps it; check it with pypdf strict)
$env:QVIEW_THUMB_DIR="<folder>"; cargo test --release duplicates_folder -- --ignored --nocapture   # duplicates of each kind in a folder, each image's nearest (also group_timings)
$env:QVIEW_BENCH_FILE="<file>"; $env:QVIEW_MARKS_OUT="<png>"; cargo test --release marks_sheet -- --ignored --nocapture   # marks of every kind drawn as saving does, timed
```

Toolchain: stable MSVC Rust plus VS 2022 Build Tools. `.cargo/config.toml` links the C runtime statically (`crt-static`, ~180 KB): the exe imports only system DLLs, no `VCRUNTIME140.dll` (check the import table after adding a native dependency; a `RUSTFLAGS` variable would override it). In the Bash tool, `cargo` is not on PATH; prefix commands with `export PATH="$HOME/.cargo/bin:$PATH"`. A running `qview.exe` locks the release binary; `build.py` closes it first (WM_CLOSE posted to its windows with a title, the visible ones, else the hidden ones (`post_close`; `taskkill` without /F skipped a minimized window), so settings are saved; killed after 3 s; `make_release.py` likewise) and only touches copies under this project's `target`. The user often has qview open, so build with `uv run build.py`, not plain cargo. Heredocs containing Rust code break the Bash tool (lifetime apostrophes); write source files with the Write tool or a Python script.

## Architecture

- **`main.rs`** creates the `loader::Loader` and asks for the file from the command line *before* `eframe::run_native`, so decoding overlaps window creation (reference on an RTX 4070 Ti: main entered ~20 ms after process creation, window created ~145 ms, first frame ~160 ms; a 14.7 MP JPEG decodes in ~80 ms, so the window is the limit). The window icon is `embedded_icon(64)`, rasterised by `build.rs` (`icon::rgba(64)` at start-up took 6 ms). Renderer is **glow**, not the default wgpu, and image textures are uploaded directly (`texture.rs`). eframe default features are off (no accesskit, no wgpu). Every window is cloaked (`DWMWA_CLOAK`) in `App::new` while still hidden and shown by `App::uncloak` once it has painted `PAINTED_TO_SHOW` (3) frames (and is maximized, when it is to be; `UNCLOAK_TIMEOUT` 1 s at most): eframe shows it after its first frame, but Windows showed it before that frame reached the screen, a white flash. A window saved maximized is created normal (`MAXIMIZE_WHEN_SHOWN`; one saved in full screen is created maximized the same way), because winit shows a window created maximized before it is painted: a white flash. Maximizing it after eframe shows it appeared in two steps (normal size at (0,0), then maximized at (-11,-11)), so `App::new` maximizes it, cloaked, with `SetWindowPlacement` (`win::show_maximized`: the restore rectangle is the one saved as `window_normal` from `GetWindowPlacement`'s `rcNormalPosition`, not saved in full screen, or `DEFAULT_SIZE` centred; eframe saves a maximized window with its maximized size, and `ShowWindow(SW_MAXIMIZE)` left that as the size the window was restored to), and `App::uncloak` waits for the maximized frames. Trace it by polling `IsWindowVisible`/`IsZoomed`/`GetWindowRect`/`DWMWA_CLOAKED` after launch. `normalize` repairs Explorer's `"C:\"` → `C:"` argument.
- **`instance.rs`**: one window per exe. `main` calls `instance::forward` before anything else is started: the first start owns the mutex `Local\qview.<hash of the exe path>`; a later one finds the message-only window of the class of the same name (made by `instance::listen` in `App::new`, on the UI thread, so winit's loop dispatches its messages), sends the normalized path in `WM_COPYDATA`, gets the main window back as the answer, calls `SetForegroundWindow` on it (the newly started process may) and exits. It waits up to 5 s for that window (the first start makes it ~150 ms in, or may be closing) and runs on its own if there is no answer. `App::ui` takes the last received path (`instance::take`) and opens it. A minimized window is restored by the message window; with a new path it is cloaked first (it would show the old image until the new one is decoded) and `App::uncloak` shows it once `current_on_screen` held at the start of a frame (`Cloak`, 1 s timeout), the same mechanism as the maximized start. Per exe path, so the installed copy and `target\release` do not take each other's files.
- **`loader.rs`**: N worker threads (2–3) take paths from a shared priority queue that the UI replaces wholesale (`Loader::want`), so files the user has skipped are never decoded; files being decoded finish anyway. A worker marks the file `done` before sending the result and `poll` clears that, so `want` never re-requests a file whose result is on its way; `Loader::forget` (called by `App::forget_files` after a save or undo) marks a busy or done file `stale`, and `poll` drops its result, decoded from the old contents, so it is asked for again. `decode` reads the whole file, guesses the format from content (extension as fallback; a JPEG on disk, `is_jpeg_file`, goes to WIC first, `read_wic`, which decodes as fast as `image`'s zune-jpeg and gives premultiplied BGRA itself: a 31.7 MP 4:4:4 scan 250 ms against 340 + 44 of conversion, a 17.5 MP photo 63 against 66 + 21; `image` if WIC fails, and always in archives), applies the EXIF orientation, shrinks to `max_side` (the GPU's `max_texture_side`, set on the first frame; 16384 before that) and converts to `Pixels`: premultiplied BGRA (the driver's native order) with every mip level, made by `half` on the worker (2x2 box; in linear light by default, `loader::set_linear_mips`, `avg4_linear` with sRGB tables, opaque pixels the short way, half-transparent ones unpremultiplied first; of the stored packed bytes, `avg2`, with View → Filtering → Reduce in Linear Light off, `Cmd::LinearMips`, `App::linear_mips` persisted as `linear_mips`, which `main::setting_flag` reads before the first decoding and whose change forgets every decoded image; levels of `BAND_PIXELS` or more in row bands on up to 4 threads), so the UI thread converts nothing (14.7 MP JPEG: decode ~80 ms, BGRA ~14 ms, mips ~12 ms linear, ~4 ms stored; `phase_timings` measures it, `mip_timings` the levels both ways). `Meta` keeps the file's real dimensions, so zoom percentages refer to the file even when the texture is shrunk, and `Meta::decode_ms`, the worker's time for the file, which the status bar shows ("Decoded in N ms").
- **`app.rs`**: `current` is the file the user is on, `shown` is what is on screen; `shown` stays the previous picture until the current one is decoded (no blank flashes), and `View::next_image` runs only when `shown` switches. `cache` holds textures of `wanted()` = current, the next in the direction of travel, the previous, and up to `AHEAD` more ahead within `CACHE_BUDGET` pixels (every image counted as large as the current one, so the set does not change while neighbours decode), and nothing else (`update_wanted`). Decoded results wait in `pending`: `poll_decoded` makes one texture per frame (the current image first), because a large upload stalls the frame. A texture starts at the mip level the image is shown at (`start_level`, `view::mip_level`); the levels below are uploaded from `partial` in a frame with nothing new to upload, or at once when the view needs them (`complete_current_if_needed`, before painting). Keyboard commands run before the panels are drawn; menu/toolbar/mouse commands are queued in `clicked` and run after, followed by a repaint. `run(Cmd)` is the single place where commands take effect. Deletion runs `win::recycle` on a thread (`poll_delete` then moves to the next image), after `confirm_delete` (`dialogs.rs`) unless `App::confirm_deletion` is off (File → Confirm Deletion, `Cmd::ConfirmDelete`, persisted as `confirm_delete`; the dialog's "Don't ask again", `dont_ask_delete`, turns it off): files then go at once with a notice naming them, folders are always asked about. Renaming (F2, `Cmd::Rename`, the File menu and both context menus) opens `App::rename`, a modal (`ui/dialogs.rs`, the name selected up to its extension as in Explorer, `folder::check_name` for what Explorer refuses, errors shown in it); `App::rename_to` renames with `std::fs::rename`, and `App::moved` moves the decoded texture, its pending levels, the gallery thumbnail, the selection and the favourite to the new path (nothing is decoded again), all pairs of a batch at once (every old name taken out before any new one goes in: `01→02, 02→03` would otherwise mix them up), then the folder is listed again for the new place in the order. Ctrl+Z (`Cmd::Undo`, File → Undo Rename/Save) undoes the last of `App::undo` (`Undo::Rename` and `Undo::Save`, each of one or several files, this session's, at most `UNDO_STEPS` and `UNDO_BYTES` of old contents): a rename back through the same `move_file`, a save by `edit::restore` (or deleting the file Save As made), with a notice; deletions cannot be undone (restoring from the Recycle Bin was judged not worth it). `App::modal_open` covers it with the other modals (keys and the wheel are theirs). When a listing does not contain `current` (deleted or renamed outside, or never there), `poll_scan` moves to the file that would follow it (`folder::insertion_point`) with a notice, so that browsing keeps working. Wheel browsing is accepted anywhere in the window (Windows routes the wheel to the window under the pointer) unless a popup or modal is open.
- **Rotating, flipping and cropping** (`crop.rs` state and geometry, `ui/crop.rs` the frame and the bar, `edit.rs` saving, `exif.rs`): `[`/`]` only turn the view (`View::turns`) and H/V mirror it (`View::mirror`: `View::flip` is a left-to-right mirror applied before the turns, so a mirror on screen also turns the other way; `view::paint` flips the UVs) until Ctrl+S (`Cmd::Save`, `App::save`) saves it; the status bar notes the angle. C (`Cmd::Crop`, `App::start_crop`) puts a `crop::Crop` over the image: the frame in pixels of the image as shown (turned), dragged by `crop::grip`/`crop::dragged` (edges, corners with or without `Aspect`, inside to move, outside for a new one), turned with the image (`Crop::turn`); the view switches to `Zoom::Fill` and gets its zoom back in `end_crop`. While cropping `input::Mode::Crop` maps Enter to Save and `App::run_in_crop` lets only zoom, panning, rotation and flips (`Crop::mirror`), full screen and the bars through; `check_crop` ends it when its image is no longer on screen. `App::save` sends an `edit::Job` (turns, flip, the crop in whole pixels unless it is the whole image, the upright size it was chosen on) to a thread; a format that cannot be saved over (`edit::can_overwrite`: not one of `edit::Format`, or a lossy WebP) goes through Save As (`pick_save_path`, rfd; the name from `edit::suggested_name`: `_crop`, `_rotate` or `_flip` added once, English in any language, numbered past existing files). `edit::save`: a JPEG only turned or mirrored gets its EXIF orientation composed with them (`turned_orientation`; `exif::with_orientation` adds a missing tag by copying the first IFD to the end, `exif::minimal` when there is no EXIF) and its XMP `tiff:Orientation` digit patched, the scan data untouched; anything else is decoded (`image`, or `loader::read_wic`), mirrored, turned, cropped and encoded (JPEG quality 92, PNG, lossless WebP, TIFF, BMP) with its ICC profile and EXIF (`exif::for_new_pixels`: orientation 1, Pixel X/Y Dimension, the IFD1 thumbnail unlinked). `edit::write_file` writes a temporary file beside it and `win::replace_file` (`ReplaceFileW`) puts it in place; a file saved over is not made anew if it was renamed or deleted meanwhile, and when `ReplaceFileW` fails with ERROR_UNABLE_TO_MOVE_REPLACEMENT (the original already gone) the temporary file is renamed into place or kept, never deleted. Save With Options (`Cmd::SaveWithOptions`, Ctrl+Alt+S, File menu; `ui/save_options.rs`: `App::save_options`, a `SaveOptions` modal of width and height kept in proportion or not, a percent with 25/50/75/100, the format, a JPEG's quality, `App::save_quality` persisted as `save_quality`, 92 by default; Save As… or Enter goes on to `App::save_with`, which `save` also is, with the format first in `pick_save_path`'s list and `_resized` when shrunk and nothing else; `edit::Job::resize` shrinks after the marks, `edit::resized`: Lanczos 3, premultiplied when there is alpha, never larger; `Job::quality` is the JPEG encoder's and turns off the lossless JPEG path; `resize_timings` times it, 0.2-0.5 s for 24 MP). Without metadata (`Job::strip`: the dialog's "Without metadata" check box, `SaveOptions::strip`, `_nometa` in the name; or Save Without Metadata, `Cmd::SaveWithoutMetadata`, in both context menus under More beside Convert To, `save_without_metadata_item`, enabled by `can_convert`, refused like `ConvertTo` in an archive and with a folder cell: `App::strip_metadata` makes `_nometa` copies of `targets()` beside their files in `save_format` without a dialog, through `start_save` as a conversion with `Saving::stripped` for the notices; the current image turned as shown): `encode_anew` carries no EXIF (the ICC profile stays), and a JPEG only turned goes through `edit::strip_jpeg` instead of `turn_jpeg`: the APP1 (EXIF, XMP), APP13 (IPTC) and COM segments dropped, `exif::minimal` of the composed orientation after APP0 when it is not 1, the scan data untouched, so `Saved::lossless` holds). `App::still_saving` refuses another save or conversion while one runs or while `reloading` (the saved image not yet on screen again, the view still turned: a second Ctrl+S turned the file twice). File → Convert To (`Cmd::ConvertTo(edit::Format)`, `App::convert`; also the gallery's cell menu, `App::can_convert`: the current file need not be decoded, `Job::size` matters only with a crop, `edit` refuses animations) makes a copy beside the file without a dialog (`suggested_name` with no suffix, the view's turns applied, no crop), which `poll_save` only lists (`Saving::convert`), the original staying current. `poll_save` pushes `Undo::Save` with the old bytes and date, calls `changed` (decoded again, the gallery thumbnail forgotten, the folder listed again; `reloading` drops the view's turns once the new texture is on screen, so the old picture stays turned until then) and opens a file made by Save As. The encoders added about 230 KB to the exe.
- **Marks** (`annotate.rs` model, geometry and drawing into the pixels; `ui/annotate.rs` the bar, the overlay and the text field): A (`Cmd::Annotate`, View → Mark Up, `ui::menu::annotate_item`, the toolbar's `Icon::Annotate`, the image's context menu) makes `App::annotating` an `annotate::Annotating` over the image on screen (`start_annotate`, like `start_crop`: `Zoom::Fill`, zoom and pan given back by `end_annotate`; ends any crop; `check_annotate` ends it when the image is no longer on screen; the tool, colour and size kept in `App::mark_style` for the next image). Marks (`annotate::Mark`: `Shape::Rect`/`Ellipse`/`Line`/`Arrow`/`Pen` (freehand points, round caps and joins in the file, end circles on screen)/`Pixelate`/`Text`, any colour (new text and new shapes keep theirs apart, `Annotating::colours` by `slot`, black and red at first, `colour()` the one of `kind()`; the bar's six `COLOURS` as round swatches, `ui::annotate::swatch`, the chosen one ringed, as MetalMPV's accent colours, and `own_colour`, a colour wheel or the colour picked, opening `colour_picker` (MetalMPV's: a square, a hue bar, `#rrggbb`, R/G/B) in a `Popup`), a size in units of its `annotate::Measure` (`Line` width, `Text` height, `Block` side; each its own `range`, `Annotating::sizes` per measure, `measure()`/`size()` the chosen mark's else the tool's; `ui::annotate::size_slider`, drawn by hand, logarithmic, its rail light, filled to the handle, the value beside it in image pixels), an `ArrowHead` for arrows (`Blunt`/`Normal`/`Sharp`, `proportions`: the head's length in line widths and half width; `annotate::arrow` takes it; chosen with `ui::annotate::head_button`s in the bar while `Annotating::kind()`, the chosen mark's tool else the tool, is the arrow), a second colour of text (`Mark::contrast`, `Annotating::set_contrast`: the outline's or the plate's letters', None for black or white by `annotate::outline`; `ui::annotate::contrast_choice` beside the text styles but Plain, a disc half black half white while automatic, a popup with Automatic, black, white and `picker_fields`; `Preset` keeps it as `#rrggbb` after the text style), a `TextStyle` (`Plain` by default, `Outline`, `Plate`: `annotate::plate` fills a rounded rect of the colour behind black or white glyphs, as tall as the nominal lines or the glyphs, `Plain`) and a `TextFont` (family, bold, italic; Segoe UI, not bold, by default; `annotate::families` lists the system fonts' families, `ui::annotate::font_choice` a `ComboBox` narrowed by `Annotating::font_filter`, B/I beside it; the SVG's `font-family` is the family quoted as a CSS string, then `'Segoe UI'`, since usvg falls back to a serif)); selecting a mark (`Annotating::select`) puts its style in the bar. `annotate::Preset` (tool, colour, size, text style, font, head; `to_line` writes an arrow's head after the text style, then `b-`/`-i` flags and the family to the end of the line, lines without them read with the default font and head): only the user's, `App::mark_presets` (six built-in ones were dropped as unwanted), persisted as `mark_presets` (`to_line`/`parse`, a line each), the bar's Presets menu (`presets_menu`: apply, × remove, Save Current Style). The bar is two rows: the tools wrap left of Save/Save As/Cancel (a right-to-left layout holding a wrapping left-to-right one; they overlapped before), then the style, wrapped are in pixels of the image as shown (turned), sizes from `annotate::unit` (a 600th of the longer side: `line_width`, `font_size`, `block`, a power of two; `blocks` every side the block range gives, 4 to 1024). The list of the marks (`App::marks_panel`, a right panel under the bar, `App::mark_list`, persisted as `mark_list`, on by default; the bar's List, O): a row per mark, the topmost first (`kind_icon`, the colour, `describe`, the size in pixels, or ↑/↓/× (`Annotating::reorder`, `delete`) on the row under the pointer or chosen); a click chooses, a double click on text edits it (`Annotating::edit_text`), the chosen row is scrolled to when the choice changes, and the mark of the row under the pointer (`Annotating::hovered`, taken by `overlay`) is outlined on the image. The slider and the picker change the chosen mark directly, one Ctrl+Z step per run (`Annotating::restyling`). `input::Mode::Annotate` and `annotate_command` map R/E/L/A/D/P/T (`Cmd::MarkTool`), 1-6 (`MarkColour`), O (`MarkList`), [ ] (`MarkSizeStep`, `Measure::stepped`: a quarter, twice for blocks), Enter (Save); `App::run_in_annotate` takes those, Ctrl+Z (`Annotating::undo`, a stack of the marks before each change), Delete (the chosen mark), the bar's Clear (`Annotating::clear`, every mark, one Ctrl+Z step), Esc/Cancel (twice within 4 s when there are marks, `discard_asked`; a close of the window too, `App::hold_close` sending `CancelClose`) and lets only zoom, panning, full screen, the bars, the dialogs, Copy Image, Print and Wallpaper through. `ui::annotate::overlay` (from `image_area`, instead of the crop frame; no panning, navigator, context menu or wheel browsing then): a drag starts on the chosen mark's handles (`crop::grip`/`crop::dragged` for frames, the ends of an arrow), on a mark to move it (`Mark::moved`, kept in the image), or draws a new one (`Drag::New`; Shift a square, circle or 45° arrow; dropped under `MIN_DRAWN` points); a click chooses; with Text a click opens `Annotating::typing`, an egui `TextEdit` in an `Area` below the text (`TEXT_ID`; Enter commits through `consume_key`, Shift+Enter a new line, Esc cancels, losing the focus commits; while it is open `App::ui` runs no keys and keeps its focus), a double click edits text. On screen frames, ellipses and arrows are egui shapes (`annotate::arrow` gives the head for both), text is `annotate::render_text` (resvg with `svg::system_fonts`, the database SVG text uses, loaded with the families on the mosaics' thread, `read_mosaics`; `paint-order="stroke"` outline black or white by luma; drawn into a texture cached by text, size, colour, style and font, `Annotating::texts`; text larger than `TEXT_LIMIT` or the GPU's largest texture drawn smaller by `text_scale` and shown enlarged, in the file within twice the image's side: a texture too large aborted in egui_glow; `xml_text` drops what XML refuses), and pixelated areas are the mosaics (`read_mosaics` on a thread at start: `edit::render` of `as_shown`, a premultiplied average per block for each of `blocks`, `NEAREST` textures drawn over the image and clipped to `crop::pixels` of the area). `edit::Job::marks` (Save with `_marked`, `as_shown` for Copy Image, Print, Wallpaper; `print::plain` false with marks; no lossless JPEG path with marks; the size check as with a crop) are drawn last in `edit::transform` by `annotate::draw`: premultiplied, every pixelated area's blocks from the pixels before any are filled (under the rest), then tiny-skia strokes, the arrow's head filled, text pixmaps at `p.round()` plus their offset; no alpha stays no alpha. `cargo test --release marks_sheet -- --ignored --nocapture` with `QVIEW_BENCH_FILE` and `QVIEW_MARKS_OUT` draws every kind into a PNG, timed. ~95 KB of the exe.
- **`view.rs`**: scales are *physical* screen pixels per image pixel, the zoom shown (1.0 = 100% regardless of Windows scaling, 2.0 = 200%, above 1 enlarged; divide by `pixels_per_point` for points). `Zoom::Fit` never enlarges, `Zoom::Fill` fits with enlargement, `Zoom::Cover` fills the window and crops; the mode chosen with 1–4 (`View::mode`, `choose`, persisted as `zoom`) survives browsing, `Zoom::Scale` (from zoom steps) falls back to it on the next image, unless `View::keep` (L, not persisted) keeps the zoom and the pan offset for the next images (only the rotation resets). `place` clamps the pan offset and snaps the image corner to a physical pixel. Rotation is done by permuting UV coordinates in `paint`, not by rotating vertices. `mip_level(scale)` is the level a texture may start at: the nearest to the shown size, 0 from 71% up. The navigator (N, `Cmd::Navigator`, View → Zoom, `App::navigator`, persisted as `navigator`, on by default) shows over an image larger than the window (`pannable`), not while cropping: `navigator_rect` (in `view::Corner`, `App::navigator_corner`, Navigator Position, `Cmd::NavigatorCorner`, persisted as `navigator_corner` as `bottom_left` etc., bottom left by default; `NAVIGATOR_SIDE` points on the long side at most, a quarter of the area's short side), `navigator_window` (the part on screen), drawn by `App::paint_navigator` with the image's own texture through `paint_tinted` (its small mip levels; nothing decoded or uploaded for it, an animation's frames follow); `App::navigate` (pressed or dragged: `View::centre_on` the point under the pointer, `nav_grab` keeping where a window was grabbed; the wheel over it zooms about the centre). Hide Navigator When Idle (`Cmd::NavigatorHides`, `navigator_hides`, off by default): `navigator_alpha` keeps it for `NAVIGATOR_HOLD` after the image's place last changed or while it is under the pointer, then fades it over `NAVIGATOR_FADE`, repainting only then.
- **`wic.rs`**: Windows Imaging Component, for what the `image` crate cannot read (HEIC/HEIF and AVIF with the Store extensions when libheif is missing or fails, camera RAW, JPEG XR, DDS, any installed codec). The interfaces are declared by hand (`windows-sys` 0.61 has no Imaging module at all, so the GUIDs are written out too) and called by vtable index (`Com::method`, indices from `wincodec.h`); `wic::tests` checks them against Windows' own PNG and JPEG decoders. `decode` gives premultiplied BGRA (or straight RGBA for `loader::read`) and the EXIF orientation from the `System.Photo.Orientation` policy, not applied; `size` reads only the header (`header::read` uses it for these formats). `extensions()` (a `OnceLock`, warmed by a thread in `main`) is the installed decoders' extensions not in `folder::EXTENSIONS`, plus HEIC/HEIF/AVIF always (their error then names the Store extension, `wic::needs`); `folder::is_image` adds them to listings and the Open dialog, but not to the file associations. `wic::takes(path)` routes those extensions straight to WIC (RAW files are TIFF inside: `image` would show their small preview); other files try `image` first and fall back to WIC on failure (`loader::decode`/`read`). Callers keep COM initialised for the thread (the loader workers, the thumbnail workers, the Auto proportions thread), and each such thread keeps an uninitialised decoder of every container it has used (`wic::keep_codec`, released by the outermost `win::com_init` guard, which counts nesting): releasing the last HEIF decoder took ~260 ms (its HEVC pipeline shut down), so without it a 12 MP iPhone HEIC took ~280 ms for its header and ~500 ms to decode, with it ~5 ms and ~160 ms. The HEIF decoder applies the container's rotation itself and reports orientation 1 (a portrait iPhone photo decodes 3024x4032). `cargo test codec_list -- --ignored --nocapture` prints the installed decoders; `$env:QVIEW_WIC_FILE="<file>"; cargo test --release wic_file -- --ignored --nocapture` times one file, `wic_scaled` a JPEG at 1/2, 1/4 and 1/8 through `IWICBitmapSourceTransform` (DCT scaling; not used: the entropy decoding it cannot skip is most of the time, see `doc/PERFORMANCE.md`).

## Conventions

- Every user-visible string goes through `tr!("English", "Русский")`; the language follows the Windows UI language (`i18n::system_lang`, set in `main`) unless chosen in About (`i18n::LangChoice`; applied in `App::new` from the settings and at once when changed). Strings are built every frame, so nothing caches translated text; the tree's top-level names come from Windows in its own language. Log messages and decoder errors stay English.
- Persisted state is only the window geometry (eframe `persist_window`), the menu bar/toolbar/status bar flags (the menu bar hidden with M, `Cmd::ToggleMenuBar`; the context menus then start with Show Menu Bar, `ui::menu::show_menu_bar_item`), whether Esc in the viewer closes the program instead of opening the gallery (`App::esc_closes`, off by default, `Cmd::EscCloses`, `ui::menu::esc_closes_item` in the View menu and the gallery toolbar button's context menu; a slideshow, full screen and cropping still take Esc first), the image background, the zoom mode, the sort order and the gallery's cell size, fill choice and tree width (`save`, keys `menu_bar`, `esc_closes`, `confirm_delete`, `toolbar`, `status_bar`, `background` as `#rrggbb`, `checker`, `filter` as `bilinear`/`bicubic`/`pixels`, `linear_mips`, `zoom` as `actual`/`fit`/`fill`/`cover`, `thumb_size`, `thumb_columns` (0 when the slider sets the size), `thumb_fill`, `thumb_badges` as `type,dimensions,size,modified,created` (any of them, none by default), `thumb_cache` and `thumb_cache_mb` (see `thumbcache`), `thumb_aspect` as `16:9` etc. or `auto`, `tree_width` in points, `info_panel`, `info_width` in points, `info_histogram`, `info_histogram_channels` as `luma`/`rgb`/`r`/`g`/`b`, `info_colour`, `slideshow_seconds`, `slideshow_loop`, `save_quality`, `language` as `system`/`en`/`ru`, `sort` as `name`/`modified`/`taken`/`size`/`type`, `sort_descending`, `favorites_sort` (also `added`), `favorites_sort_descending`, `check_updates`, `last_update_check` in Unix seconds, `by_folder`, `folders_folded`, `path_follows_grid`, `navigator`, `navigator_hides`, `navigator_corner`, `editor` and `editor_name` (see `editors`), `mark_presets` and `mark_list` (see Marks), `window_normal` as `left,top,right,bottom`); egui memory is not persisted. - The image area has no frame, so its background is `App::clear_color` (`App::background`, presets in `app::background_presets`, View → Background, whose colour picker is drawn inline in the submenu so the menu stays open). Text and the spinner drawn on it use `app::ink_on` to stay readable on light colours. Under the image (and the placeholder thumbnail) `App::paint_checker` draws a checkerboard (`App::checker`, persisted, on by default; `view::checker_texture`, 2x2 texels repeated with nearest filtering, squares a whole number of screen pixels from the image's pixel-snapped corner), seen only where the image is transparent.
- The release profile has `panic = "abort"`: any panic closes the program. `f32::clamp` panics when its bounds cross (a frame rounded a little past the image), so `crop.rs` uses its own `clamp`; sizes from files may be 0 (a GIF's screen), which `loader::read_image` refuses.
- The version comes from `Cargo.toml` (`main::VERSION`, shown in About and on the start screen). Between releases it is the next version with `-dev` (`0.2.0-dev`), and `build.rs` appends `git describe --tags --always` to it (`0.2.0-dev (v0.1.0-2-g4bd494d)`, rerun on commits, branch switches and new tags; no `--dirty`, which would go stale); a release version is shown as is. Release: drop `-dev`, commit, tag `vX.Y.Z` (release.yml checks the tag against `Cargo.toml`), then set the next `-dev` version.
- GUI checks: on this machine the OpenGL client area cannot be captured from outside: NVIDIA shows it through an overlay plane, so `PrintWindow` returns it white and `BitBlt`/`CopyFromScreen` shows the desktop behind the window, even for a normal-sized window; the rendering is checked by the user. The caption (non-client area) can still be probed with `PrintWindow` from a DPI-aware process (`SetProcessDPIAware`, otherwise the capture is cropped on a scaled display). Keys can be sent with `PostMessage(WM_KEYDOWN/WM_KEYUP)` to the window without touching the user's input; posted mouse moves are useless because Windows immediately reports the real pointer leaving. A launched qview window takes the focus, so whatever the user types at that moment goes into it (Backspace browses, Esc closes): warn the user before launching test windows. Before any simulated global mouse/keyboard input, warn the user too.
