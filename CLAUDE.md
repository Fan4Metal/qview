# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

qview is a Windows-only image viewer, written in Rust with egui/eframe 0.36. Priorities: start-up speed, instant browsing, full keyboard control, no settings dialog. `README.md` / `README.ru.md` are the user-facing docs and must be kept in sync (both languages, cross-linked, formal tone).

## Commands

```
uv run build.py                  # closes a qview.exe running from target\, then cargo build --release
cargo test                       # unit tests (view geometry, key map, folder order, decoder, mip levels, formats)
cargo clippy --release --all-targets   # must stay warning-free
python tools/make_release.py     # tests, release build, dist\qview_<ver>_Setup.exe (Inno Setup 6, tools/setup.iss) and _portable.zip
$env:QVIEW_TRACE=1; .\target\release\qview.exe <file>   # start-up, decode and texture upload timings on stderr
$env:QVIEW_BENCH_FILE="<file>"; cargo test --release phase_timings -- --ignored --nocapture   # decode phases of one file
```

Toolchain: stable MSVC Rust plus VS 2022 Build Tools. In the Bash tool, `cargo` is not on PATH; prefix commands with `export PATH="$HOME/.cargo/bin:$PATH"`. A running `qview.exe` locks the release binary; `build.py` closes it first (WM_CLOSE via `taskkill`, so settings are saved; killed after 3 s) and only touches copies under this project's `target`. The user often has qview open, so build with `uv run build.py`, not plain cargo. Heredocs containing Rust code break the Bash tool (lifetime apostrophes); write source files with the Write tool or a Python script.

## Architecture

- **`main.rs`** creates the `loader::Loader` and asks for the file from the command line *before* `eframe::run_native`, so decoding overlaps window creation (reference on an RTX 4070 Ti: main entered ~20 ms after process creation, window created ~145 ms, first frame ~160 ms; a 14.7 MP JPEG decodes in ~80 ms, so the window is the limit). The window icon is `embedded_icon(64)`, rasterised by `build.rs` (`icon::rgba(64)` at start-up took 6 ms). Renderer is **glow**, not the default wgpu, and image textures are uploaded directly (`texture.rs`). eframe default features are off (no accesskit, no wgpu). A window saved maximized is created normal (`MAXIMIZE_WHEN_SHOWN`, as in disk_flashlight, because winit shows a window created maximized before it is painted: a white flash), but unlike disk_flashlight it is not maximized after eframe shows it (that appeared in two steps: normal size at (0,0), then maximized at (-11,-11)): `App::new` cloaks it (`DWMWA_CLOAK`), maximizes it with `ShowWindow(SW_MAXIMIZE)`, and `App::uncloak` shows it once a maximized frame is presented (1 s timeout, so it can never stay invisible). Trace it by polling `IsWindowVisible`/`IsZoomed`/`GetWindowRect`/`DWMWA_CLOAKED` after launch. `normalize` repairs Explorer's `"C:\"` → `C:"` argument.
- **`loader.rs`**: N worker threads (2–3) take paths from a shared priority queue that the UI replaces wholesale (`Loader::want`), so files the user has skipped are never decoded; files being decoded finish anyway. A worker marks the file `done` before sending the result and `poll` clears that, so `want` never re-requests a file whose result is on its way. `decode` reads the whole file, guesses the format from content (extension as fallback), applies the EXIF orientation, shrinks to `max_side` (the GPU's `max_texture_side`, set on the first frame; 16384 before that) and converts to `Pixels`: premultiplied BGRA (the driver's native order) with every mip level, made by `half` (2x2 box, packed-byte averages) on the worker, so the UI thread converts nothing (14.7 MP JPEG: decode ~80 ms, BGRA ~14 ms, mips ~5 ms; `phase_timings` measures it). `Meta` keeps the file's real dimensions, so zoom percentages refer to the file even when the texture is shrunk.
- **`app.rs`**: `current` is the file the user is on, `shown` is what is on screen; `shown` stays the previous picture until the current one is decoded (no blank flashes), and `View::next_image` runs only when `shown` switches. `cache` holds textures of `wanted()` = current, the next in the direction of travel, the previous, and up to `AHEAD` more ahead within `CACHE_BUDGET` pixels (every image counted as large as the current one, so the set does not change while neighbours decode), and nothing else (`update_wanted`). Decoded results wait in `pending`: `poll_decoded` makes one texture per frame (the current image first), because a large upload stalls the frame. A texture starts at the mip level the image is shown at (`start_level`, `view::mip_level`); the levels below are uploaded from `partial` in a frame with nothing new to upload, or at once when the view needs them (`complete_current_if_needed`, before painting). Keyboard commands run before the panels are drawn; menu/toolbar/mouse commands are queued in `clicked` and run after, followed by a repaint. `run(Cmd)` is the single place where commands take effect. Deletion runs `win::recycle` on a thread (`poll_delete` then moves to the next image). Wheel browsing is accepted anywhere in the window (Windows routes the wheel to the window under the pointer) unless a popup or modal is open.
- **`view.rs`**: scales are image pixels per *physical* pixel (1.0 = 100% regardless of Windows scaling; divide by `pixels_per_point` for points). `Zoom::Fit` never enlarges, `Zoom::Fill` fits with enlargement, `Zoom::Cover` fills the window and crops; the mode chosen with 1–4 (`View::mode`, `choose`, persisted as `zoom`) survives browsing, `Zoom::Scale` (from zoom steps) falls back to it on the next image. `place` clamps the pan offset and snaps the image corner to a physical pixel. Rotation is done by permuting UV coordinates in `paint`, not by rotating vertices. `mip_level(scale)` is the level a texture may start at: the nearest to the shown size, 0 from 71% up.
- **`texture.rs`**: image textures are made with glow directly (`frame.gl()`, `register_native_glow_texture`), not with `ctx.load_texture`: egui_glow's RGBA `glTexImage2D` plus `glGenerateMipmap` took 70–150 ms of the UI thread per 15 MP photo on the RTX 4070 Ti (NVIDIA 610), BGRA with `UNSIGNED_INT_8_8_8_8_REV` and the levels from the worker take 3–10 ms once the driver's memory pool is warm. The driver's first pass over new memory costs ~25 ms plus ~1 ms per MB whatever is done (a warm-up only moves it), hence starting at the shown level (`GL_TEXTURE_BASE_LEVEL`) and completing later: the first 14.7 MP photo is on screen ~85 ms sooner. `glGetError` waits for the driver thread (20–60 ms), so release builds do not call it. `Texture` deletes its GL texture on drop, so `App::on_exit` clears the cache while the context lives; `Picture` holds it in an `Rc`.
- **`input.rs`**: `command(key, modifiers, repeat)` is the key map (unit-tested); `1` is Actual, `2` Fit (shrink only), `3` Fill (fit with enlargement) and `4` Cover (fill and crop); numpad `/` and `*` remain as aliases. Numpad `*` has no `egui::Key` and arrives only as `Event::Text("*")`; `Ctrl+C` arrives as `Event::Copy`. egui-winit falls back to the physical key when the logical one is not Latin, so letter keys work in the Russian layout. `ctx.options.zoom_with_keyboard` is turned off so Ctrl+Plus/Minus do not scale the UI. Only browsing, panning and zoom repeat when a key is held.
- **`folder.rs`**: lists a folder on a thread (`scan`), filters by `EXTENSIONS`, sorts with `win::logical_cmp` (`StrCmpLogicalW`, Explorer's order), and always keeps the opened file in the list even with an unknown extension.
- **Start screen and About** follow disk_flashlight: `ui::app_icon` takes the smallest of the icons embedded at build time (`main::embedded_icon`, 64/128/256 px) not below the display size and minifies it with mipmaps (cached in `App::start_icon` / `App::about_icon`); `App::start_screen` shows icon, name, version and a hint when nothing is open; About (`dialogs.rs`) shows icon, name, version, description, author, and the homepage/license lines only when `repository`/`license` are set in Cargo.toml, plus where the settings live.
- **`ui/`**: `impl App` methods for the menu bar, the toolbar (icons are painted vector shapes, buttons use `Sense::CLICK` without `FOCUSABLE` so Space/Enter never activate them), the status bar and modals. `App::ui` also surrenders any widget focus before handling keys. A modal opened by a key ignores keys in that frame (`dialog_fresh`), otherwise F1 would close the Shortcuts window it just opened.
- **Window caption**: the window is created with the Windows theme and egui switches it to dark at the end of the first frame; Windows 10 repaints the caption with the new colours only on the next non-client repaint, so the caption was white until a focus change. Unlike disk_flashlight (theme follows Windows, `refresh_caption` with `WM_NCACTIVATE` off and on after a change), qview is always dark, so `App::new` sets `DWMWA_USE_IMMERSIVE_DARK_MODE` (`win::dark_caption`) while eframe still keeps the window hidden: the caption is dark from the first shown frame and nothing is repainted. The `WM_NCACTIVATE` flip visibly flickered the caption at start-up; do not bring it back. Check with a pixel probe of the caption in a `PrintWindow` capture.
- **`win.rs`**: Win32 helpers (Recycle Bin via `SHFileOperationW`, `explorer /select`, `ShellExecuteW`, CF_HDROP via `clipboard-win`, local date via `SystemTimeToTzSpecificLocalTime` + `GetDateFormatEx`/`GetTimeFormatEx` in the user's locale, UI language, message box).
- **`icon.rs`** draws the app icon procedurally (two photo prints, the one behind tilted, the front one a sunset over mountains and a lake, `icon::photo`, which the file type icons reuse) and encodes `.ico` files (`encode_ico`); `cargo test icon::tests::preview_sheet -- --ignored` with `QVIEW_APP_ICON_SHEET=<png>` writes it at all sizes plus the small ones enlarged; `build.rs` includes it via `#[path]`, writes a multi-size `.ico` and embeds it with `winresource` as icon ID 1 (the lowest ID, which Explorer shows for the exe).
- **File associations**: `filetypes.rs` is the table of registered formats (ProgID `qview.<id>`, extensions, Type column names, icon band/letter colours from the classic 16-colour palette); `folder::EXTENSIONS` must list the same extensions (a test checks). `type_icon.rs` draws each type's icon at every size (page with a folded corner, the app icon's landscape from 32 px, a band with the extension in a 3x5 pixel font placed on whole pixels at a whole scale, so 16 px stays sharp); `build.rs` embeds them as icon IDs 101+ (`filetypes::icon_id`) and the registry refers to them as `"qview.exe",-<id>`. `cargo test preview_sheet -- --ignored` with `QVIEW_ICON_SHEET=<png>` writes a sheet of all icons at all sizes. `assoc.rs` registers per user under HKCU (ProgIDs with DefaultIcon and open command, `OpenWithProgids` of each extension, `Applications\qview.exe`, `Software\qview\Capabilities` listed in `RegisteredApplications`), then `SHChangeNotify(SHCNE_ASSOCCHANGED)`. It never writes `UserChoice` (protected by a hash; the default is the user's choice): "Choose as Default…" opens `ms-settings:defaultapps?registeredAppUser=qview`, and `assoc::defaults` reads `UserChoice` only to show the state. File → File Associations… (`dialogs.rs`) and `qview --register` / `--unregister` use it. Its test writes into a scratch key under `Software\qview_test_<pid>`, never the real associations; do not register the real build on the user's machine without asking.

## Conventions

- Every user-visible string goes through `tr!("English", "Русский")`; the language follows the Windows UI language (`i18n::system_lang`), there is no setting. Log messages and decoder errors stay English.
- Persisted state is only the window geometry (eframe `persist_window`), the toolbar/status bar flags, the image background and the zoom mode (`save`, keys `toolbar`, `status_bar`, `background` as `#rrggbb`, `zoom` as `actual`/`fit`/`fill`/`cover`); egui memory is not persisted. Do not add a settings dialog: the few choices live in the menus.
- The image area has no frame, so its background is `App::clear_color` (`App::background`, presets in `app::background_presets`, View → Background, whose colour picker is drawn inline in the submenu so the menu stays open). Text and the spinner drawn on it use `app::ink_on` to stay readable on light colours.
- The version comes from `Cargo.toml` (`main::VERSION`, shown in About).
- GUI checks: on this machine the OpenGL client area cannot be captured from outside: NVIDIA shows it through an overlay plane, so `PrintWindow` returns it white and `BitBlt`/`CopyFromScreen` shows the desktop behind the window, even for a normal-sized window; the rendering is checked by the user. The caption (non-client area) can still be probed with `PrintWindow` from a DPI-aware process (`SetProcessDPIAware`, otherwise the capture is cropped on a scaled display). Keys can be sent with `PostMessage(WM_KEYDOWN/WM_KEYUP)` to the window without touching the user's input; posted mouse moves are useless because Windows immediately reports the real pointer leaving. A launched qview window takes the focus, so whatever the user types at that moment goes into it (Backspace browses, Esc closes): warn the user before launching test windows. Before any simulated global mouse/keyboard input, warn the user too.
